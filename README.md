# 胶片冲洗参数库

面向黑白与彩色胶片冲洗者的本地参数管理工具。可以按乳剂批次登记胶片、记录显影液工作液寿命、编排冲洗配方，并把每次实冲温度、时间和样片结果沉淀为下一批次的修正依据。应用为纯前端单页应用，不需要后端服务或外部接口。

## Docker 一键启动

在项目根目录执行：

```bash
cp .env.example .env && docker compose up -d --build
```

停止服务：

```bash
docker compose down
```

## 数据存储说明

- IndexedDB 数据库名：`gbfilmdev-db`
- Dexie 版本：`version(1)` 创建 `films`、`developers`、`recipes`、`runs` 四张表并建立常用查询索引。
- 迁移：
  - `version(2).upgrade(...)` 为已有记录回填 `schemaRev: 2`。
  - `version(3)` 为 `runs` 增加试片密度字段，并新增 `calibrations`（校准版本，发布后不可变）与 `suggestions`（每配方一条待冲建议）两张表。升级时旧实冲记录与参数原样保留、不进入读数配对；每个旧配方按**手工校准**补齐 v1 版本与待冲建议，引用已报废工作液的建议直接置为待确认。
- 首次打开数据库时通过 `populate` 写入丰富的胶片、显影液、配方、实冲记录以及一条完整的校准链演示数据（含一致发布、读数冲突待选定、换批 / 报废后待确认等场景）。
- 数据保存在当前浏览器，不随容器重建而丢失；更换浏览器或清理站点数据前，可在顶部导航点击“导出数据”下载 JSON 备份（备份包含校准版本与待冲建议）。
- 所有新增和更新动作在写入 Dexie 前均会去除响应式代理，避免 `DataCloneError`。

## 校准链规则

乳剂批次 → 显影液工作液 → 配方 → 实冲读数 → 校准版本 → 待冲建议，按配方串成一条链：

1. **录入实冲必须登记试片密度**。同一配方未被消费的两条读数相差 **不超过 0.15** 才能发布校准版本；锚点密度取两条平均，下一批建议时间按锚点密度对目标密度的偏差修正（带安全限幅）。
2. **两条读数相差超过 0.15 时保留两条冲突**，界面逐条列出，只能由人工选定其中一条发布（`manual-pick`），系统**不会自动平均**——自动平均会把待冲建议算错。未选中的读数继续保留，可与后续新读数再次配对。
3. **版本发布后待冲建议立即失效并重算**（每配方仅一条建议，原地更新）；已完成的实冲记录和版本发布时的乳剂 / 工作液 / 配方快照保持不变。
4. **工作液报废或胶片更换乳剂批次**（同型号同画幅出现新批号）时，相关配方的待冲建议先退回**待确认**，人工复核后可恢复有效；报废原因优先于换批原因。
5. **重复提交不会多出版本**：同模式、同依据读数重复发布直接返回既有版本；并发双击由 IndexedDB 读写事务串行化保证。所有多表写操作（发布、报废、换批、录入实冲）都在单个 Dexie 事务内，**写入失败整体回滚恢复原状态**。

## 核心功能与路由表

| 路由 | 页面标题 | 核心功能 |
| --- | --- | --- |
| `/` | 参数速查台 | 按胶片、稀释比、推拉档检索参数，查看最近冲洗记录 |
| `/films` | 胶片型号与乳剂批次台账 | 登记乳剂批次，按画幅和有效期筛选，观察余量 |
| `/developers` | 显影液配制与余量 | 登记工作液、换算容量、查看剩余可冲卷数并标记报废 |
| `/recipes` | 配方表 | 编排配方，按胶片和稀释比筛选，改温度即时重算时间 |
| `/runs` | 冲洗记录与结果评价 | 录入实冲温度与时间，查看补偿建议并回写配方注释 |

未匹配的路由会重定向到 `/`。
